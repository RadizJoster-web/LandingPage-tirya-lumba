## Celah / Risiko yang Masih Ada

1. workflow.pdf tidak dapat dibaca oleh model (input PDF tidak didukung);
   ekstraksi manual hanya menghasilkan tabel font, bukan teks isi. Alur
   bisnis dari PDF karena itu BELUM terverifikasi. Alur yang saat ini
   diimplementasikan: home -> register + OTP -> login -> /daftar portal ->
   form murid/guru -> status di profil. Perlu konfirmasi apakah ini sudah
   sama dengan workflow.pdf.

2. API live belum diuji: server http://localhost:5000 tidak berjalan
   (permintaan timeout), jadi integrasi runtime belum terbukti, baru
   kontrak statis yang cocok.

3. URL unggahan bisa kosong dan berpotensi menolak submit: dokumentasi
   endpoint `/upload-file/student/payment` dan `/upload-file/instructor`
   hanya membalas `{ success, message }` tanpa URL berkas, padahal submit
   pendaftaran mewajibkan `paymentProofUrl`/`cvUrl`/`profilePictureUrl`.
   Kode mengirim string kosong bila URL tidak ada (`api.ts:213-216`,
   sudah ditandai `shortcut:`). UI hanya memberi peringatan; backend bisa
   membalas 400.

4. Status pendaftaran tidak real-time: hanya tersimpan di localStorage,
   hilang bila storage dibersihkan atau dibuka di perangkat lain.

5. Reschedule tanpa endpoint: `/guru/atur-ulang-jadwal` memakai fallback
   WhatsApp (`views/atur-ulang-jadwal/index.tsx:14-17`).
   Bukan poin revisi eksplisit, tetapi kemungkinan ada di workflow.

6. Animasi keluar belum ada: permintaan "animasi in/out" baru terpenuhi
   separuh (hanya animasi masuk).

7. Semua perubahan belum di-commit; `AGENTS.md` ikut termodifikasi.
